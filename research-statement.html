Research statement (agentic AI)

Two proposals for postdoctoral research. Both are proposals, not results: nothing on this page reports an experiment that has been run. They build on practices I already use and document publicly: a pre-registered study design (FaultLine), negative controls that can overturn a reported alarm (DriftSentinel), and verifier-based rewards in my current LLM post-training and evaluation study (in progress, unpublished).

Proposal 1

Verifier-rewarded post-training for research agents

Idea
Post-train agents that carry out research tasks, such as running an analysis or an experiment, with reinforcement learning whose reward comes from executable verifiers: checks that the produced work runs, reproduces the numbers it states, and passes its own tests.
Headroom check
Before each RL stage, score the current checkpoint with the same verifiers on a development set. Run the stage only if there is measurable headroom, that is, tasks the model solves sometimes but not always. If the model almost never or almost always passes, the reward carries little learning signal; the stage is skipped and the skip is recorded.
Sealed test
Fix the test set and the analysis plan, and register both, before training begins. The test set stays sealed until all training and model-selection decisions are frozen, and the comparison that decides the outcome, including what counts as no improvement over supervised fine-tuning, is stated in advance.
Failure condition
If the verifier-rewarded stages do not improve the sealed test over the supervised baseline, that is the reported result.
Proposal 2

An auditable co-scientist for forecasting

Idea
An agent that proposes and runs forecasting analyses, for example on spatio-temporal energy data of the kind used in my published work, but may report a finding only after it passes executable checks.
Checks
Every reported finding must pass negative controls, meaning the same pipeline run on a setting where the claimed effect cannot exist, and leakage audits, meaning time- and site-separated splits with no information from the evaluation period in features or preprocessing. A finding that fails is reported as failed, together with the check it failed.
Motivation
In my own public work such checks changed the conclusion: DriftSentinel's 20-seed negative controls overturned an initial "8/8 critical" drift result, and in FaultLine a baseline added after the registered programme closed (time since the last fault) beat the model, which the study reports as its headline finding.
Evaluation
Compare the findings the agent would report with and without the check gate, and record how many ungated findings the checks reject.
Failure condition
If the gate rejects almost nothing, or rejects findings that an independent re-analysis confirms, the checks are not informative, and that is reported.

Status: both directions are proposals for postdoctoral work; no results exist for either. Current work is listed under LLM post-training and agentic systems.
